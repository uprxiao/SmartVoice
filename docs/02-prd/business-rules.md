# 方案 B 业务规则（v0.3）

2026-10-17：依据用户授权细化。目标为参考产品核心口述体验；本文规则是 SmartVoiceInput 的实现约定，不宣称等同于参考产品未公开服务端。FR 范围由 [PRD](PRD.md) 定义；接口、字段和测试必须遵循本文件。

## BR-01 范围与数据归属

- V1 仅 `dictation`：账号、口述、忠实整理、插入、词库/修改学习、历史、基础洞察、基础管理后台。
- 词库、历史、设置和统计由自有服务端按账号持久化；同账号在另一设备重新请求可读到同一份数据。无独立云同步开关、第三方托管、离线编辑合并或实时跨端推送。客户端不另建一套权威词库/历史数据库。
- 不实现翻译、语音命令、问答、订阅、团队、推广、云同步模块。原型相关占位在正式产品隐藏。个性化展示“持续学习中”及累计学习次数，不伪造百分比。
- 设备列表保留；远程踢设备、管理员 Web 重置密码、用户删除、运行时修改服务地址不在 V1。服务地址由集中构建配置决定；密码恢复是运维命令，不增加产品页面。

## BR-02 内容与隐私

| 数据 | 可到哪里 | 保留 |
|---|---|---|
| 音频 | 客户端、自有服务端、经配置批准的内网 ASR | 成功、取消、无语音、上传不完整立即释放；完整 ASR 失败的重试资格600秒截止，本地PCM清理≤截止后1秒、工作进程退出确认≤截止后2秒，见 BR-05 |
| 本次 raw_text/refined_text | 自有服务端、当前账号客户端；本次转写可发给已配置 LLM | 默认永久；账号可选 7/30/90 天 |
| 输入框原有全文、原值和选区快照 | 仅客户端当前会话内存 | 插入/观察结束清除，不上传、不写日志 |
| 本次插入后的修改片段 | 自有服务端；分类需要时可发已配置 LLM | 仅局部 before/after 与来自本次插入的左右各最多 80 Unicode 码点；词条语境最多 3 份 |
| 账号凭证 | 服务端保存密码哈希/refresh 哈希；客户端主进程安全存储 | 按 BR-03 撤销/过期 |
| 日志 | 请求 ID、阶段、错误码、耗时、用量 | 不含音频、转写、输入框正文、词条语境、密码或 token；默认 14 天 |

ASR 部署限定回环/内网；LLM 允许本地、内网或公网，业务代码使用统一 provider。部署白名单和网络出口共同约束，不能仅凭 `http`/`https` 判断地址是否内网。无后台浏览用户正文的权限/API。

缩短历史保留期前，界面说明将永久清理超过新期限的历史正文并要求确认；取消不保存，确认后按新期限清理，延长期限不能恢复已删正文。历史到期时删除转写、整理稿、纠错原片段和撤销快照，只保留无正文元数据及统计；已经形成的词条与其有限学习语境属于词库，随词条编辑/删除，不随历史过期而丢失。历史页明确说明此区别。到期判断使用会话第一次终结时间，重试不延长期限；每小时清理，最迟到期后 1 小时完成。到期后立即禁止从接口读取正文，即使清理任务尚未执行。

部署默认每日加密数据库备份、保留 7 天。在线清理不会改写已有备份，因此隐私说明须告知备份副本最多滞后 7 天清除，且仅限恢复用途。恢复开放前清空备份中的全部历史正文、会话提示及学习原片段/撤销快照，避免旧保留设置使已删正文重新出现；统计和独立词库按明确的备份恢复点恢复，恢复点之后的变更可能丢失。

## BR-03 账号、设备和鉴权

- 邮箱去首尾空格并统一小写，最长 254 字符；密码 8–128 Unicode 码点，保留原始空格、不做截断，不强制字符种类。重复邮箱 409；账号不存在和密码错误统一 401。正确凭证但账号禁用返回 403。
- access 有效期 900 秒；随机 refresh 有效期 30 天，固定到期、不滑动续期；V1 不轮换 refresh，服务端只存哈希。每次刷新校验账户和所属登录会话，不要求未过期 access；刷新失败清除本机登录态并提示重新登录。
- 每次登录建立登录会话（JWT `sid`），绑定账号、客户端类型和桌面安装 ID；同一安装 ID 重登撤销该设备旧登录会话。安装 ID 为本机随机 UUID，不采集硬件指纹。
- 退出仅撤销当前登录会话；其他设备保留。禁用账号事务内撤销全部登录会话，下一次 HTTP/握手立即拒绝；进行中的 WS 最迟 5 秒终止并取消任务。重新启用不恢复旧凭证。
- Desktop：Main 持有凭证，safeStorage 加密后保存；无法使用安全存储则本次仅内存登录并提示。Renderer 不得获取 token。Admin Web：access/refresh 均仅在页面内存中；刷新页面重新登录，不放 localStorage，不使用身份 cookie。
- 注册只能创建普通用户；管理员从运维命令初始化。后台接口逐请求查询当前角色；禁止禁用自己或最后一个 active 管理员。

## BR-04 录音、状态和断线

- 2026-10-20用户明确：快捷键开始/停止只切换录音与胶囊，不显示、恢复或激活主窗口；保持主窗口原有可见/隐藏/最小化状态。结果返回、插入失败或无光标也不自动弹主窗口，结果入历史；用户需要复制时主动打开。后台采集仍不节流，显式Dock/菜单/二次启动打开行为不变。

- 默认快捷键 `CommandOrControl+Shift+Space`，按一下开始、再按结束；按平台已知保留表（含等价写法归一化）判断，命中或明确注册/保存失败保留旧配置；不保证检测任意第三方自定义快捷键占用、不抢占，保存成功不表示全局排他。具体表范围、提示和原子保存见[快捷键范围决定](shortcut-conflict-decision-20261019.md)。V1 不承诺 Option/Fn 单键与按住说话。HUD 不抢焦点，处理阶段可取消，应用内 Escape 取消，外部不全局劫持 Escape。
- PCM s16le、16 kHz、单声道、250 ms；正常帧 4000 样本，最后一帧允许 1–4000。停止时先排空本地尾帧，再发送 audio.end。最大 180 秒；恰好到上限自动收尾，恶意继续超发拒绝。
- V1 验收 ASR 必须支持稳定 partial；stable_text 单调扩展，provisional_text 可修订。partial 不插入目标，也不作为最终历史原文。
- 每账号最多一个 `created/streaming/finalizing/refining` 会话。2026-10-19 用户确认：已完成结果无论是否复制、插入或确认，都不阻止快捷键或“新的一段”开始下一次录音；上一段已持久化的原文/整理稿继续按历史保留设置供查看和复制。无可用光标时不插入、不自动寻找输入框。新一段在自己的结果返回后独立捕获当前目标，旧结果/目标/迟到事件不得串入。正在录音、处理、插入或重新指定期间仍互斥。服务端无可用容量时创建即返回 429，不允许无限排队。后端音频确认只代表完整校验并接收，不代表 ASR 完成。
- 未 ACK 音频上限 2000 ms。连接关闭、ACK 等待超过 2000 ms、录音设备丢失或系统休眠时停止采集；上传中断不补传、不拼接，不返回不完整结果，提示重新录音。audio.end 的 ACK 丢失时先查询 audio_complete：true 可继续查询结果，false 才认定上传中断；不重发音频。断线恢复取到的结果仅展示/复制或由用户显式重新指定，不自动插入。
- 前端 `idle/preparing/recording/finalizing/refining/ready/review/inserted/error/cancelled` 是界面态；后端 `created/streaming/finalizing/refining/ready/empty/failed/cancelled` 是处理态。插入另有状态，不能混在后端处理终态中。
- cancel 在 ready 前原子生效，取消优先阻止尚未提交的结果，迟到回调丢弃；ready 后的“关闭结果”只结束展示，不抹除历史，已插入不能用 cancel 撤回。空音频/无语音进入 empty，提示“未识别到语音”，不调用整理、不插入。

## BR-05 重试与结果版本

2026-10-18 用户确认：同一账号的其他 desktop 设备可以显式重新整理已有历史文本；不要求由创建设备执行。新整理尝试绑定实际发起者的登录会话，退出或撤销该登录后不能提交迟到结果；历史会话的创建设备与原登录来源不改。ASR 重新识别、录音连接以及插入资格/回执的原设备限制保持；跨账号不能读取或重试，admin_web 不执行整理。

| 条件 | retry_kind | 用户操作与结果 |
|---|---|---|
| ASR 失败、audio.end 已确认、内存完整音频仍在 | asr | 显式“重新识别”；同 session 新 attempt，保留原 session 统计身份 |
| ASR 失败但不完整/过期/服务重启丢失缓存 | none | 提示“音频已不可用，请重新录音” |
| raw_text 可用、整理故障导致回退 | refine | 显式“重新整理”，不依赖音频 |
| 目标校验失败且明确未写入 | none | 复用已有结果，允许用户重新指定目标或复制；不重新调用模型 |
| 插入成功或结果不确定 | none | 不再次自动插入；结果不确定时提示检查目标并手动复制 |
| cancelled/empty/正文已过期 | none | 不能恢复本轮；需要重新录音 |

完整失败音频只在内存中用于重试。设唯一截止 `D=首次 ASR 失败时间+600秒`，重试、读取、转池或回滚均不重置 D。2026-10-18 用户确认将逻辑截止与清理收尾区分：

- 到 D 立即失去音频重试及处理资格；不得接纳新 ASR 重试、继续使用过期音频或提交其迟到 ASR 输出。入口、派发及提交校验不能依赖定时扫描或数据库缓存状态已更新；第599秒开始的重试仍受原 D 限制。
- 本地服务进程持有的 runtime、provider、队列参数及其他 PCM 引用最迟在 `D+1秒` 清空；独立工作进程的音频工作副本通过 terminate/kill 收尾，最迟在 `D+2秒` 确认退出。两个期限均从 D 起算，不串成3秒，不是额外识别时间。退出确认前不得归还或复用该执行资源；无法确认时继续隔离并报告故障，不能标清理成功。
- ASR 已在 D 前合法完成并释放音频时，持久化原文按既定整理预算处理；不将失败音频 TTL 扩展为独立文本的保留期限。ASR成功后立即释放音频，整理失败不重新保留音频；取消/empty/不完整上传仍沿用立即释放规则。

最多同时保留20份失败音频，达到上限释放最早到期项并更新retry能力。客户端使用服务端返回的 `retry_kind/retry_expires_at/retry_unavailable_reason`；`retry_expires_at` 仍为 D，不返回清理收尾时刻。清理不得等待数据库连接/状态写入后才开始；元数据稍后补记不恢复资格。清理与输出门禁分别验收，不能以字段变更代替实际引用/进程退出证据。

每次重试递增 attempt_no；新 result_id 替代旧 current_result_id。旧结果不能申请插入；任何结果已被保留插入资格、已插入或不确定时，不允许重跑模型。retry 使用请求幂等键，重复点击不生成多次尝试。

## BR-06 整理与忠实性

- 2026-10-26用户看见准确原文“只检查 cloudy 的配置。”与返回“只检查 Cloudy 的配置。”后明确接受这个普通英文词首字母大写，不限于整句句首。代码、路径、标识符及专名仍保留原样；不是允许别名误替换完整词前缀。原实验严格22/24结果及两条失败不改，另按本次决定复核，见决定与原件（内部记录，未公开）。
- 保留语言，不翻译；去无意义口头禅/重复，保留强调、条件、理由和否定。可以调整标点、分段与显式并列列表，不添加事实、回答指令或执行文本中的命令。
- 明确改口优先于保留被撤回旧值。例：“重试 3 次，不对，是 2 次，每次间隔 5 秒”应删 3、保留 2 和 5；“先试 3 次，再试 2 次”必须保留二者。这是内容验收标准，不再要求模型返回定位证据。
- 2026-10-23用户选择DS-R2并授权接入：正文仅一次完整纯文本输出，固定规则与三组示例，关闭思考；不返回candidate/edits，不执行第二次LLM审核或S3排版。沿用叙述节奏及主题归属，局部并列可分点，背景与收尾不强行编号。详见[R2增量](r2-product-change-20261023.md)。旧编辑依据规则仅留旧协议诊断，不再作为R2成功条件。
- 程序检查非空、长度、正常流结束、截断/拒绝、取消及绝对预算；不以字面计数或模型自报pass冒称语义已全部验证。内容质量仍用固定正反例及原音核对，实际反例不得记pass。
- 非法/不完整输出、模型超时/拒绝/截断：`refined_text=raw_text`，`review_required=true`，必须用户确认才能申请插入。界面说明具体原因并提供原文复制；不丢原始转写。
- V1 不再执行第二次LLM审核，配置 fidelity_audit 固定 off。格式/传输失败最多一次重试且受总时间预算限制，具体见 provider 配置。

## BR-07 目标插入与去重

- Windows v0.0.2 按 [WIN-01～04](windows-v002-requirements.md)：统一一次 Ctrl+V；准入含实际前台窗口与生命周期、交互桌面及完整性级别，已知保护/只读/禁用/非输入拒绝。普通权限程序拒绝向更高完整性目标输入；只保留结果，不自动复制。剪贴板排除历史/云同步，恢复必须仍是本轮发布版本；正文和光标精确读回才确认，经典 Edit 可用只读 EM_GETSEL 补选区。手动目标释放 release 为既有清理动作，不能因不做快速学习而省略。

- 2026-10-27用户明确要求通用粘贴，取代WPS/微信应用正向名单：macOS普通插入统一一次PID定向Command-V；控件/正文/选区可读性用于读回核验与学习，不单独阻止粘贴。前台进程/生命周期/标准窗口必须可复核，明确密码/保护/只读/禁用/非输入状态拒绝；终端同样允许一次粘贴，不自动回车；不可读控件的未知安全属性无法保证识别，已明示此限制。严格读回才inserted/学习，否则unverified且不自动重试。见[通用决定](universal-paste-decision-20261027.md)。

- 2026-10-20 用户进一步明确以实际粘贴前的最新光标为准，替代较早的“结果返回时冻结目标”规则；录音、等待结果及结果返回后到粘贴前均允许移动光标、改变选区或切换应用。不因先前捕获的目标已改变而拒绝，不写回已离开的旧窗口；只使用最终输入目标的当前状态。拒绝密码/只读；终端按2026-10-27本人决定允许单次粘贴、不自动回车；最终无可用目标仍保存历史供复制，不阻止下一段。见[最终光标决定](final-paste-focus-decision-20261020.md)，当前实现尚待修订。
- 正常 review_required=false 且最终目标可输入时自动插入 refined_text，无需每次确认；原文仅展示/复制。非空选区替换实际粘贴时的当前选区，保留其他文字，不使用旧原值覆盖用户的新输入。历史重试/恢复不自动插入；用户显式重新指定仍沿用一次执行、去重及结果保留规则。
- 服务端先分配插入资格，客户端将 result_id/insertion_id 的执行标记持久化后才调用 native helper；执行标记不含正文。重复事件/响应/重启恢复不能再次执行原操作。
- 结果状态：`reserved/inserted/failed/unverified`。只有读回确认写入后的值与预期一致才报 inserted；确定零写入报 failed；无法确认报 unverified。reserved 在崩溃后也视为不确定，禁止自动重试；failed 才允许用户显式另发 insertion_id 重试同结果。
- 原生能力明确判定尚未写入且目标可安全验证时，允许一次剪贴板粘贴兜底。写入不确定时不再粘贴第二次。粘贴后仅在剪贴板版本仍是本轮写入版本时恢复旧值，避免覆盖用户新复制内容。
- 不自动 Enter/发送。终端按2026-10-27本人决定走通用一次Command-V，不自动回车/发送；目标对正文内换行的处理由其自身决定，不作无执行保证。控件不可读时通用粘贴只报告“已尝试，未核验”；无法确认前台窗口或明确受限时才复制降级，不标“已输入”。
- 先前WPS及微信专用例外保留于原决定作历史，当前统一按通用机制执行；不把原准备或失败追认为新路线通过。

## BR-08 修改学习

- Windows v0.0.2 平台范围见 [WIN-12](windows-v002-requirements.md)：本版不新增输入后修改观察，明确展示自动纠正学习暂不可用；已有词库仍用于识别/整理，手动管理可用。不修改 Mac 或其他设备的账号学习偏好。以下观察/学习规则继续约束已支持的平台与后续实现，不将 v0.0.3 草稿自动纳入 Windows 本版。

- 默认启用，可在设置关闭；只观察已确认 inserted 且 observable=true 的本次片段。300 ms 采样，静止 15 秒或总计 60 秒结束；计时从插入确认开始，片段变化重置静止计时，不重置总时限。输入法组合态完成后再计算差异。
- 2026-10-20现场补齐：已知composing期间即使文字静止15秒也继续等提交；commit后重新计算15秒稳定期，60秒绝对截止不变。unknown不当作已提交。中文连续替换按中文词边界补齐共同前后缀（如按钮→按键），保留32码点、单处差异及保护内容限制；不把单字最小差异误作完整中文词。明确term自动入库、仅提示并可撤销；旧客户端手动确认不得冒称自动；当前客户端已移除该入口。
- 本机读回成功后立即开始有限观察，同时提交插入回执；发送纠错前必须确认该回执已在服务端入库。回执不确定时只重发同一回执，不重插入；观察窗口结束仍未确认则跳过学习、清除局部片段并提示词库未更新。
- 仅接受一个连续的词语替换，before/after 各 1–32 Unicode 码点，不含换行、数字/路径/否定改写；不学习纯插入、删除、整段改写、切换控件、前后原有内容变化。offset 统一按 Unicode 码点，后端验证 before 与该插入片段匹配。
- 一次观察结束时只提交一次稳定的最终差异，提交前保存在当前片段内存；多次编辑以最终 before→after 为准。分类输出 `term/suggest/ignore`、歧义标记与原片段证据；只有 term、无歧义、证据可匹配、局部校验通过且无别名冲突才自动 learned。其余可能的词语修正保留内部 suggested，但默认不应用、不提示确认卡；非词语修正 ignored。不使用未经校准的模型自报数值置信度，分类边界必须用固定正反样本验证。
- 2026-10-20用户确认默认自动交互：仅实际learned提示并可撤销，suggested不弹确认卡、不由客户端自动confirm。兼容旧版本的 suggested 确认通过独立 confirm 操作，不复用“首次提交+confirm=true”改变同一幂等请求。学习请求重复不增加词条或计数；学习失败不影响已经插入的文字。
- 异步分类完成后，应用学习的事务再次核验账号可用、学习仍开启、正文未过期/清理、词条版本和容量、别名冲突；条件变化不得覆盖后来的编辑或重新写回已清正文。
- 撤销只在词条仍等于该学习事件产生的版本时恢复；已有其他修改返回 409，不能覆盖新修改。历史过期后不可恢复已清理的撤销快照，词条仍可手动编辑/删除。
- 2026-10-28 修订（快速纠正学习，S1 待评审）：发送/清空/控件失效/焦点离开时立即判定，不再要求静止15秒（15秒空闲判定保留为兜底，60秒上限不变）；最终修改须满足“读取前安静≥M、读取到触发按键之间无其他按键”，否则跳过；输入法状态未知时以该按键顺序条件代替一律放弃，明确组字中仍不学；按键只在观察窗口内记录时间与类别，不记字符；冻结后的学习不被下一段口述取消；Electron/Chromium 系应用读不到时可开启其辅助功能（无新增权限）；撤销辅助功能后已冻结的学习继续提交；终端插入过不了核验，不学习。本条覆盖上文“静止15秒结束”“unknown不当作已提交”及“观察窗口结束仍未确认则跳过”的相应部分，其余不变。详见 [快速纠正学习需求变更](fast-correction-learning-decision-20261028.md)。
- 2026-10-19 用户明确修订：词库能识别并纠正即可，不要求同一句只改第一处、区分专名与普通含义。唯一有效的正确词 claw、别名 cloud 可作用于多处完整别名，包括“cloud 云服务”；两处均纠正为 claw 可验收。语境可作提示，不再作为每处纠正的必需语义许可。该放宽只适用于有效词库映射，不允许凭空发明替换、破坏无关内容、数字/单位/路径/URL/否定/引号内字面值；完整词边界、别名归属歧义和快照版本规则保留。实现方式先按同一模型与固定文本对比 参考方法 和当前方法，再依据实测选择，不因需求修订自动记通过。

## BR-09 词库和 CSV

- 正确词 trim 后 1–64 码点；norm=NFKC+casefold；每账号最多 5000 条。别名最多 10 个、每个 1–64 码点，归一化去重，不能等于正确词。正确词与别名允许词间普通空格，禁止换行及 Unicode Cc 控制字符。scope 固定 default，不引入团队/应用作用域。
- 正确词归一化重复返回 409。别名可以有歧义：多个词共享别名时标记歧义，不自动学习/强制替换，由语境提示决定；模型不确定时保持原词。手动编辑 source 变为 manual；删除别名同时清除绑定该别名的语境。
- 每词 version 从 1 开始；用户 dictionary_version 从 0 开始，每次实际词条变更+1，无变化不增加。单会话创建时固定词库版本快照；处理中编辑只影响下次会话。
- CSV 为 UTF-8（允许 BOM），必需列 term，可选 aliases（用分号分隔）；标准 CSV 引号处理，最多 1 MiB/1000 数据行。逐行处理，合法行导入，非法行返回行号/错误；相同词+别名集跳过，已有同词但不同内容返回冲突，不静默覆盖；同一文件重复导入不产生重复。
- ASR 提示选最近更新的最多 100 个正确词、总计不超过 2000 码点；整理按原始转写匹配词/别名选最多 50 条及有限语境、总计不超过 4000 码点，平局按 norm 排序。上限截断可观察但不泄露日志正文。

## BR-10 统计与保留

- 服务端统一 UTC 时间存储；自然日采用部署级 `Asia/Shanghai`，V1 不提供时区切换。date_from/date_to 均为该时区自然日，含首尾；最多 366 天。
- 会话数：接收到至少 1 个有效音频样本的 session 数，重试不新增。日活：当天有上述会话的去重用户数；归属创建日，跨午夜不拆分。取消/失败计会话和接收音频时长。
- 口述字数：当前有效非空结果中 Unicode 类别 L（字母/汉字）或 N（数字）的码点数；忽略空格/标点，英文按字母，不称“英文词数”。总口述时长仅统计这些有结果会话的原始音频时长；平均速度=总字数×60000/这些会话 audio_ms，保留一位小数，零分母显示 0。
- 活跃/当前连续/最长连续天数与热力图按有音频会话的自然日；今日未用时从昨天向前计算当前连续；今天和昨天均未用为 0。热力图依据每日会话数分档 0、1、2–4、5–9、≥10。
- 处理成功率=有非空结果的会话/(有结果+failed+empty)，排除 cancelled 和处理中；回退原文也算产生结果，另算回退率=当前 review_required 结果/有结果。插入成功率=至少一次确认 inserted 的会话/有结果会话；复制、failed、unverified 不算插入成功。
- 管理后台总接收音频包含取消/失败；与首页“成功口述时长”分开标注。模型用量按实际调用（含重试/分类，以及历史实际审核调用）统计；供应商未返回 token 时为 unknown，不当作 0。ASR 增量多次解码的处理样本时长与用户录音时长分列。
- 学习次数为成功应用的学习事件累计值，撤销不抹去历史次数；词条总数只计当前有效词条。历史正文清理不改变已固化的统计贡献。重复回执/页面读取不增量累加。

## BR-11 页面反馈和兼容边界

- Windows v0.0.2 的权限区只显示麦克风与输入能力，不显示 macOS 辅助功能授权。关闭主窗口隐藏到托盘、保留录音进程，菜单打开/退出；再次启动调出或重建主窗口。自启仅 Windows、默认关、启动进托盘，系统禁用与应用偏好分开读回。快捷键保留 Shift+Space/Control+Space；双语文案、多屏及真机边界见 [WIN-05～11](windows-v002-requirements.md)。

- 登录/注册、权限引导、首页、历史、词库、设置、HUD/结果卡、后台为 V1 页面。权限引导只做麦克风/辅助功能检查和试说，不引入新营销流程。
- 所有读取页面有加载、空、失败/重试状态；提交按钮防重复；错误说明可操作路径。服务不可用时能查看已有页面，发起录音前提示服务状态；不承诺离线识别或离线编辑。
- 历史仅“全部/听写”，可复制原文或整理稿；有 retry_kind 时显示对应重试按钮。正文已清理的会话不显示在正文历史列表，仍可贡献统计。保留设置旁解释清理和词库独立保存。
- 必须能自动插入并读回的基线：macOS TextEdit 纯文本、Chrome 普通 input/textarea；Windows 记事本、Chrome 普通 input/textarea。VS Code、Office/WPS、IM、富文本分别实测；全部目标按 BR-07 通用单次粘贴，无法核验不报成功/不学习/重试，明确受限或前台窗口不可确认时复制降级；不承诺覆盖每种控件。
- 界面 zh-CN/en；快捷键/语言本机持久化，语言同时保存账号偏好；退出切换账号清空界面缓存和观察任务。关于显示实际版本；帮助仅含权限/快捷键/失败恢复说明，V1 不增加自动更新系统。

## BR-12 并发容量与后台控制（v0.3）

- 当前目标20个不同账号同时录音/识别/整理并取得正确结果；未来服务器可提高运行上限。每账号仍一个活动会话，登录在线不占额度，ready/failed/empty/cancelled终态释放业务槽；重试重新申请。
- 初始运行上限20，仅首次初始化生效；管理员可在有效部署上限内设置正整数。数据库持久化并校验version，重启不恢复旧默认；值与实测能力独立，不声称调大设置即获得算力。
- 调低须确认，已接纳任务不中断；活动数小于新上限才恢复接纳。无接纳槽时创建/重试429 CAPACITY_EXCEEDED，不排录音队；同账号活动冲突409 ACTIVE_SESSION_EXISTS。
- 普通用户不可读写容量管理；管理员看到负载、排队、拒绝/回退与采样时间，无私人正文。未验证容量必须明确标示；保存冲突、超时、失败不得显示成功。
- 模型可有限等待且计入既定总预算，ASR/LLM执行并行度由部署配置，不与会话上限捆绑。满额和故障仍按原失败/原文待确认规则，不能把降级结果当正常容量通过。
- 原型入口admin-capacity；配置/API/资源边界以[并发设计](../03-architecture/concurrency-target.md)为准；20是当前测试目标而非写死的程序上限。
