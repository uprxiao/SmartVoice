# 微信不可读焦点的单次粘贴：用户决定

2026-10-27，用户明确选择：**“允许微信单次粘贴，标未核验”**。确认问题已说明：微信本轮没有提供可读的焦点控件，此模式在可复核的微信前台窗口按实际光标粘贴一次，标“已尝试，未核验”、不自动学习、不自动重试；无法可靠核验微信的选区、密码或只读属性。此次决定只扩大微信这一应用的兼容例外，WPS及其他应用规则保持各自范围。

依据：三次零写入失败（内部记录，未公开）及只读定位（内部记录，未公开）。权限true，微信窗口可读，系统/微信app级焦点输入控件查询均noValue，原实现因此拒绝。参考产品同框可用为本人对照，未推测其私有实现。旧失败及原判据保留追溯，不倒填通过。

## 采用规则

- 仅准确bundle `com.tencent.xinWeChat`；每次以实际粘贴前的当前前台位置为准。同结果至多一次派发，不主动激活或写回旧微信窗口。
- 系统AX焦点可用时沿用原可靠控件流程；仅AX返回noValue时允许刷新AppKit前台信息，并限定为仍active、未隐藏/退出的微信。其他错误或应用不获兜底。
- 不可读模式要求微信app级焦点控件确为noValue，AXFocusedWindow为属于同进程的标准窗口；窗口明确禁用、保护或只读时拒绝。PID启动代际、启动时间、同一前台窗口在捕获/校验/紧邻粘贴前均复核。窗口身份不可读就保留结果供复制。
- 此模式不具有控件/正文/选区快照，无法保证识别未知密码或只读属性，也无法检测同窗口内光标/选区改变；以实际粘贴接收位置为准。这些限制已在问题中向用户明示并获准，不宣称与可靠AX控件同等支持。
- 捕获时预选一次PID定向粘贴，不按Enter、不发送，不先尝试AX写入再改粘贴。保存/恢复剪贴板沿原竞争规则，用户更改后保留用户值。
- 发送后统一unverified/observable=false/effect=unknown，文案“已尝试，未核验”；不计可靠插入成功、不学习、不自动重试，不允许重新使用同一已尝试目标。明确未发送才可failed/零写入。
- 可读的密码/保护/只读控件和终端限制保持；这个例外不扩大到其他IM、未知应用或非标准/未知窗口。
