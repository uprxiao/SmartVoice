# 辅助功能未授权的主动申请与可见提示（2026-10-28）

## 背景

2026-10-28 本人首次安装 v0.0.4 Mac 预览包后直接口述：录音和识别正常，但结束后文字没有输入到当前输入框，界面也没有任何提示。

服务器 `insertions` 记录（只读状态与错误码，未读正文）：16:25:29–16:26:43 共 6 次自动输入均为 `failed / ZERO_WRITE`，耗时 40–90 ms（原生层直接拒绝）；本人随后授权，16:27:47 起 3 次为 `unverified / VERIFY_FAILED`（已执行粘贴，读回无法确认，属既有已知限制）。

## 根因（代码定位）

1. **从不主动申请辅助功能权限**：唯一调用系统授权框的入口是设置页按钮（`desktop/src/renderer/views/SettingsView.tsx` → `app.requestAccessibility`）。首次登录、开始录音都不检查；录音只需麦克风，因此直到最后插入才失败。
2. **失败提示不可见**：原生层返回 `PERMISSION_REQUIRED` 和“外部输入需要辅助功能权限…”，但提示只以主窗口 toast 呈现（`desktop/src/renderer/stores/session-store.ts` 的 `insert`）。用户在其他应用中口述时主窗口被遮挡；HUD 在结果就绪后约 0.6 s 无条件关闭（`desktop/src/main/app/hud-visibility.ts`），不区分插入成败。
3. **错误码被降级**：回执白名单只有 `PERMISSION_DENIED`，原生 `PERMISSION_REQUIRED` 被兜底为 `ZERO_WRITE`（`desktop/src/main/core/session-service.ts` 的 `receiptCode`），统计无法区分权限类失败。

第 2 点不满足 PRD 既有条款“辅助功能未授权……实际插入失败仍提示并提供复制”（PRD.md 录音区提示，2026-10-20），按缺陷修复；第 1 点为本次新增要求。

## 决定（本人 2026-10-28 确认“OK，针对这个，帮我修复一下吧”）

| 编号 | 规则 |
|---|---|
| AX-01 登录后申请 | macOS 登录成功（含启动时恢复登录）后检查辅助功能；未授权时调用一次系统授权框（`AXIsProcessTrustedWithOptions` prompt=true）。每个应用进程最多自动弹一次，不反复打扰；不代替用户授予权限。 |
| AX-02 录音时提示 | 每次开始录音时检查辅助功能（只查询、不弹系统框）。未授权时 HUD 在录音胶囊上方显示“未开启辅助功能，结果不会自动输入”及“去授权”按钮（打开系统设置辅助功能页）。**不阻断录音**，结果和历史照常保存。该 HUD 提示是对 2026-10-20“录音区不重复显示权限警告”规则的补充：那条规则针对主窗口录音区，本次提示只在非激活 HUD 显示。 |
| AX-03 失败可见 | 自动输入（非手动指定目标）结果为 `failed`（已证明零写入）时，HUD 不随结果关闭，改为显示失败卡片：原因文案、“复制结果”，权限类失败另有“去授权”，可手动关闭；8 秒后自动关闭；开始新录音时立即让位。`unverified` 不弹失败卡片（可能已写入，避免误报），沿用主窗口提示。 |
| AX-04 错误码对齐 | 回执时将原生 `PERMISSION_REQUIRED` 归为 `PERMISSION_DENIED`，后台可统计权限类失败。 |

不变的规则：不自动重试、不自动回车、不重复写入；HUD 复制按钮只复制当前结果整理稿到剪贴板，不触发插入；HUD 不接收、不显示整理稿全文。

## 验收

新增 TC-INSERT-22（见 `docs/04-test/test-cases.md`）。单元测试不能替代真实系统权限验证：须在 Mac 安装包上撤销本应用辅助功能授权后，按“登录 → 口述 → 看 HUD → 复制/去授权 → 授权后再口述”实际走通。
