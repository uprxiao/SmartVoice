# SmartVoiceInput PRD V2：云端 ASR 与后台 Provider 管理（增量）

2026-10-27。**状态：S1 草稿，待本人评审。** 来源：[V2 需求决策稿](cloud-asr-provider-decision-20261027.md)（Q1–Q9 已按本人答复并入）。

**与 V1 的关系**：V1（[PRD.md](PRD.md) v0.3、[business-rules.md](business-rules.md)）保持不动并继续描述 R2 版本；本文只列 V2 **新增或修改**的条款，未提及的 V1 条款全部沿用。冲突时 V2 的部署以本文为准，V1 文件不回写。本文通过评审前不改 S2/S3/S4，测试用例在 S1/S2 确定后再写。

## 1. V2 目标与范围

**目标**：服务端可部署在 Linux 服务器上，ASR 与整理模型都通过后台配置的 provider 提供；ASR 支持云端流式识别（百炼 `qwen3-asr-flash-realtime`）并保留 macOS 本地 Qwen3-ASR；单次录音最长 6 分钟（360 秒）。

| 范围内 | 范围外 |
|---|---|
| 云端 ASR provider（首个：百炼实时识别）；保留 `qwen3_mlx`（仅 macOS Apple Silicon 主机可选） | ASR 热词/词表传入云端（实验不稳定，首版不做；DeepSeek 整理阶段词库**保留**） |
| 管理后台管理多个 provider（ASR 与整理 LLM 两个列表），各自选 1 个作为当前使用 | 分类 LLM（学习分类）进入后台列表：首版仍用部署 YAML |
| API Key 加密入库；地址严格白名单；保存/切换前连通测试；审计 | 自动故障转移、按用户/按会话选择 provider、多 provider 并行 |
| 最长录音 6 分钟（360 秒，服务端静音点分段提交） | 无后台的单机版；Windows 本地 ASR；Windows 端新功能 |
| Linux 部署形态与 HTTPS/WSS | 本地 GPU（`qwen-asr`+vLLM）provider |

## 2. 角色与权限变化

| 角色 | V2 新增权限 |
|---|---|
| 管理员（`admin`） | 创建/编辑/停用/删除 provider、测试连接、切换当前 provider、查看审计；不能查看 Key 明文、不能扩大地址白名单 |
| 普通用户 | 无变化；桌面客户端不新增配置界面，只在不可用时看到明确错误 |

## 3. V1 条款变更总览

| V1 条款 | V2 变更 |
|---|---|
| PRD §1/§7 “V1 ASR 限本机/内网”“音频不出内网” | **有意变更**：允许管理员启用云端 ASR，音频流发往经白名单批准的云端地址（BR-13）。未启用云端 provider 时行为与 V1 一致 |
| BR-02 数据表“音频可到哪里”；“ASR 部署限定回环/内网” | 增加“经白名单批准的云端 ASR 地址”；其余数据边界、日志、保留不变 |
| FR-02-06 / BR-04 最长 180 秒 | 云端 ASR 上限改为 **360 秒**（本人 2026-10-27 决定），按 provider 区分（本地 Qwen 仍 180 秒），会话创建时固定并下发，客户端按下发值提示与收尾 |
| FR-02-04 / BR-04 “ASR 必须支持稳定 partial” | 沿用：云端 provider 须提供单调的 `stable_text` 与可修订的 `provisional_text`（百炼 `text`/`stash` 字段，实验 101 条中间结果 0 次违反单调，1 条录音的证据，见 §7） |
| FR-09-04 “API 地址部署时替换；不提供运行时地址编辑器” | 仍适用于**桌面客户端连接服务端的地址**；后台 provider 地址是另一类配置（FR-11） |
| FR-10 管理后台 | 新增 FR-11 provider 管理；FR-10-04 用量概览增加 provider/ASR 时长维度 |
| BR-05 失败音频 600 秒重试资格与“本地进程/工作进程清理” | 资格与截止语义不变；云端 provider 的“清理”改为：到 D 立即拒绝重试并关闭到云端的连接，服务端内存中的 PCM 最迟 D+1 秒清空，D+2 秒内确认云端会话已关闭/取消，确认前不复用该并发名额（BR-13） |
| BR-12 并发容量 | 云端 provider 不受 `execution_slots=1` 限制，受 provider 配置的并发上限与云端账号配额约束；仍不得超过后台全局上限（BR-13） |

## 4. 新增与修改的功能需求

### FR-02 语音输入（修改）

| ID | 需求 |
|---|---|
| FR-02-06′ | 最长录音时长按当前 ASR provider 决定并在会话创建时下发：云端 **360 秒**（6 分钟），本地 Qwen 180 秒；到点自动收尾并明确提示，超发拒绝（沿用 V1 机制） |
| FR-02-10（新） | 超过单段识别时长的录音由**服务端**分段提交给云端 ASR：目标段长 **30 秒**，自目标−5 秒起遇到第一个安静块即提交，目标+5 秒仍无则硬切（最长段约 35 秒）；音频实时转发、不暂存；同一会话连续多次提交，结果按序拼接；断线后的恢复见 BR-13。客户端协议与界面不变，用户无感 |
| FR-02-11（新） | 会话元数据记录实际使用的 ASR provider 与模型；云端 provider 不应用词库提示时，明确记录“本会话 ASR 未应用词库提示”，不得静默丢弃；DeepSeek 整理的 `confirmed_terms` 不变 |

### FR-11 Provider 管理（新增，管理后台）

| ID | 需求 |
|---|---|
| FR-11-01 | 管理员可在后台维护两个**独立列表**：ASR provider、整理 LLM provider。每条含：名称、类型、地址、模型名、API Key（需要时）、该 provider 的超时与并发上限等已有参数；可添加、编辑、停用、删除 |
| FR-11-02 | 每个列表有且仅有 1 条“当前使用”；可切换；当前使用项不可删除或停用。切换后**新会话**使用新项，在途会话用原项完成 |
| FR-11-03 | API Key 加密存储，主密钥由部署环境注入（不入库、不入 Git）；接口只写不读，页面仅显示“已设置/末 4 位”；Key 不进日志、审计与错误信息 |
| FR-11-04 | 地址**严格白名单**：部署配置声明允许的主机域名后缀/模式（默认含阿里云百炼 `*.maas.aliyuncs.com` 与 `api.deepseek.com`，S2 列出完整清单）。管理员只能保存白名单内的地址，不能自行扩大白名单；校验解析结果与重定向目的地，不得用域名伪装内网；非白名单地址保存被拒并说明原因 |
| FR-11-05 | 新增、修改地址/Key/模型、切换当前项前必须通过**连通性测试**（ASR：合成静音/短音频；LLM：合成文本）；失败则不保存/不切换，原“当前项”保持，并显示明确错误 |
| FR-11-06 | `qwen3_mlx`（本地）无地址，仅在 macOS Apple Silicon 部署主机可添加；其他主机选择它时说明原因 |
| FR-11-07 | 启用云端 ASR provider 前，后台显示“音频将发送到第三方云端”的确认提示，管理员显式确认；确认人与时间进审计 |
| FR-11-08 | 审计：记录谁、何时、对哪条 provider 做了什么（字段名级，不含密钥值）；不记录音频与正文 |
| FR-11-09 | 页面展示：当前 ASR/LLM 的名称、类型、模型、配置来源（后台/YAML）、最近一次连通测试结果与时间 |
| FR-11-10 | 兜底：部署 YAML 仍作启动默认；库内无可用配置或密钥解密失败时回落 YAML，并在后台标明“当前来源=YAML”；无任何可用 ASR 或 LLM 时，创建会话返回明确不可用错误，不静默降级 |
| FR-11-11 | 仅 `admin` 可访问；配置保存使用版本号防并发覆盖（版本冲突提示重新加载） |

## 5. 新增与修改的业务规则

### BR-13 云端 ASR 与 Provider 管理（新增）

1. **隐私**：云端 ASR 启用后，用户音频流发往当前 ASR provider 的白名单地址；服务端仍不长期保存音频，成功/取消/无语音/上传不完整立即释放。V2 的用户可见隐私文案须说明“当使用云端识别时，语音会发送到第三方云端识别服务”。管理员可不启用云端 provider，此时与 V1 一致。
2. **词库提示**：首版不向云端 ASR 传词表；`hint_terms` 经 provider 能力位 `supports_hints=false` 明确不应用（FR-02-11）。DeepSeek 整理仍带 `confirmed_terms`。
3. **分段（已由实验决定）**：不使用整段一次提交（535/659 秒合成语音出现循环复读或服务端 InternalError）。目标段长 30 秒；实时转发音频，不暂存；自目标−5 秒起遇到第一个安静块（250 ms RMS 低于开头语音中位 RMS 的 15%）立即提交，到目标+5 秒仍无则硬切。依据：批次 05、09——质量不低于“暂存等最佳切点”方案，停止→出字约 0.3–0.5 秒（暂存方案 4–5 秒）；固定 30 秒硬切在有停顿的语音上更差。60 秒段、扩大窗口兜底无稳定收益，不采用。
   - **补送限速**：任何落后实时的音频（断线重送）一律按 **2× 实时**发送；不限速突发会漏识别甚至被云端拒绝（批次 08：不限速 6 个会话仅 2 个成功，成功者丢失约 45% 内容），等待 1 秒不能修复，4× 有轻微损失。
   - **断线恢复**：已完成段文字保留；重连（实测约 0.4–0.5 秒）后从首个无结果的段起点重送并按 2× 追赶，追上实时后继续；单会话重试次数上限由 S2 定（实验用 8 次）。恢复后文字偶发缺失整句（实验 1/10 会话）：**本人 2026-10-27 决定不向用户提示，作为缺陷后续修复**；会话元数据记录重连次数与重送秒数。
4. **在途与切换**：切换只影响新会话；切换失败保持原配置；会话与模型调用记录当时使用的 provider/模型。
5. **失败与重试**：云端不可达、鉴权失败、限流、超时分别映射为明确错误码与用户可见提示；可重试性沿用 BR-05（完整音频仍在内存且在 D 内可显式“重新识别”）。**重试只重送未完成段**：已完成段的文字与失败音频一起只保存在内存、同一 600 秒有效期、同时清空（本人 2026-10-27 同意）；若 provider 已切换且新 provider 无法承接（如超出其录音上限），提示重新录音。重试再次向云端发送音频，属于与首次相同的隐私范围。
6. **并发**：provider 并发上限为配置项，且不得超过后台全局会话上限与部署上限；云端账号配额不足时创建/处理返回明确的繁忙/不可用，不无限排队。
7. **用量**：新增记录 ASR provider 标识、音频时长（秒）、云端调用次数，供成本核算与统计；不记录音频与正文。
8. **安全**：Key/地址变更需 `admin`；白名单只能由部署配置修改；审计与日志不含密钥、音频、转写。

## 6. 非功能需求变化

| 项 | V2 要求 |
|---|---|
| 时延 | 沿用 V1 目标（10–30 秒口述停止到插入 p50 ≤ 2 s、p95 ≤ 5 s）；V2 实验仅在个人网络下测得云端 ASR+R2 停止到整理稿中位 1.10 s（0.74–2.54 s，n=20），**目标环境尚未实测**，不据此宣称达标 |
| 隐私 | 见 BR-13；其余 V1 约束不变 |
| 安全 | 远程部署必须 HTTPS/WSS；Key 加密；白名单；审计 |
| 兼容 | 服务端：Linux（云端 ASR）与 macOS（云端或本地 ASR）；桌面客户端不变 |
| 可用性 | 云端依赖的断线、限流、欠费、账号不可用须有明确错误与恢复路径 |
| 容量 | V1 的 20 路目标在云端 provider 下需在目标环境重测，不沿用本机本地 ASR 的结论 |

## 8. 验收标准（高层，V2 增量）

- 管理员可添加多个 ASR/LLM provider，选择 1 个当前使用；非法地址、非白名单地址、连通失败均被拒绝且原配置不变；Key 全程不可读出。
- 启用云端 ASR 后，一次完整口述可识别、整理、插入；中间结果可见；失败有明确提示。
- 6 分钟（360 秒）录音可完成分段识别且不出现固定硬切式丢字（具体判据在 S3 定）。
- 切换 provider 不影响在途会话；审计可追溯。
- Linux 实机 + 真实云端 ASR + DeepSeek 端到端通过并记录延迟与已知限制；仅单测/mock 不构成通过。

## 9. 已由实验决定与待确定事项

**已决定（批次 05–09，非验收）**：段长目标 30 秒；切点“遇到第一个安静块即切、目标+5 秒硬切”；窗口内无静音时直接硬切（B 集验证 CER 0.39%），不另设兜底；不暂存音频；补送 2× 实时；断线后从首个无结果段起点重送；已提交段文字保留。实验记录见 `docs/04-test/bailian-*-20261027-0*.md`。

**仍待 S2/S3 与后续验证**：真人连续长讲话（5–6 分钟）由本人在开发完成后自测；恢复后偶发丢句的修复；3× 补送是否可用；单会话重试次数上限；白名单完整清单与默认值；云端错误码映射；加密算法与主密钥轮换方案；用量/成本字段与告警；provider 并发默认值与云端账号配额；Linux 部署清单与目标环境的延迟/断线频率实测。
