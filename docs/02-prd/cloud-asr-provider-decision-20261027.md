# V2 需求决策稿：云端 ASR provider 与后台 provider 配置

2026-10-27。**状态：草稿，Q1–Q7 已按本人答复并入，待本人整体评审。** 现有 PRD/BR 是 **V1**，保持不动；本稿描述 **V2** 的需求来源，V2 的 PRD 见 [PRD-v2.md](PRD-v2.md)（技术文档另起版本），不覆盖 V1 的“音频不发送公网”等规则。评审通过后按 S1 → S2 → S3 → S4 顺序编写，测试用例不提前编写。

## 1. 本人已表达的决定（2026-10-27 对话）

1. 服务端部署到 **Linux 服务器**。
2. ASR 按 provider 管理：**新增云端 ASR provider，保留 macOS 本地 Qwen3-ASR（MLX）**。
3. 云端 ASR 首选 **百炼 `qwen3-asr-flash-realtime`**（Qwen 官方托管的流式识别）。
4. **ASR 热词先不加**；**DeepSeek 整理阶段的词库（`confirmed_terms`）保留**。
5. 速度“可以接受”：按实验约 1 秒内出整理稿。
6. **管理后台支持配置多个 provider**：可添加多条（名称、类型、地址、Key、模型名），ASR 与整理模型各自**从列表中选 1 个作为当前使用**。
7. 暂不做无后台的单机版。
8. 云端账号**先用本人提供的**（实验用的北京 Key 是借来的，不用于正式环境）。
9. **API Key 加密存数据库**；后台同样配置 DeepSeek。
10. 地址采用**严格白名单**：服务器部署配置里写明允许的主机，管理员只能选/填白名单内的地址；新增厂商需先改部署配置。
11. **最长录音 6 分钟（360 秒，本人 2026-10-27 修订，原为 10 分钟）**，超过官方“建议 60 秒”的部分采用**分段提交**；具体切分策略见 §4.1 与第 4 批实验。
12. 接受音频发往阿里云公网（云端 ASR 的前提）；这是 V2 对 V1 隐私承诺的有意变更，须写入 V2 PRD 与用户可见文案。

## 3. 与现有文档的冲突（需要本人明确改规则）

| 现有规则 | 位置 | 冲突 |
|---|---|---|
| “V1 ASR 限本机/内网”“ASR 只可本机/获准内网，**音频不发送公网**” | `PRD.md`、`business-rules.md`（BR）、`provider-config.md` | 云端 ASR 会把音频流发往阿里云 |
| `egress_policy: deny-public`，`build_asr` 遇 `remote_base_url` 直接拒绝 | `server/app/core/config.py`、`providers/__init__.py` | 代码有意挡住公网 ASR，需改成“显式授权”而非删除校验 |
| 音频只在内存处理，失败 600 秒内可重试，本地进程 PCM 在截止后 1 秒清空 | `AGENTS.md` 5.1、BR-05 | 面向本地进程；云端需重新定义“释放”和“重试”的含义 |
| Provider 在启动时由 YAML 构建，Key 通过环境变量 | `main.py`、`config.py` | 后台配置需要运行期切换与密钥存储 |

**需要本人拍板（核心）**：是否接受把用户音频发往公网第三方（阿里云）？这改变了产品的隐私承诺，不是纯技术选择。

## 4. 设计草案

### 4.1 ASR provider 抽象（沿用现有接口）

沿用 `AsrProvider` / `AsrSession`（`prepare/open/health/close`；`feed/partials/finish/cancel`），业务层不变。新增 `bailian_realtime`：

- WebSocket 连接 `wss://<host>/api-ws/v1/realtime?model=qwen3-asr-flash-realtime`，`Authorization: Bearer`，直连并**忽略系统代理**（实验中系统 SOCKS 代理会使默认客户端失败）。
- 音频 16 kHz/单声道/PCM16，250 ms 块；沿用“按快捷键开始/结束”：手动模式（`turn_detection=null`），结束时 `input_audio_buffer.commit`，收到 `completed` 后 `session.finish`。服务端 VAD 模式不用于主路径（实验中其延迟口径无效）。
- `session.updated` 就绪、`partial` → `AsrPartial`、`completed` → `AsrFinal`；`error`/断线映射为 `ProviderError`，区分可重试与不可重试。
- 能力声明：`AsrCapabilities.stable_partial` 按实际填写；**新增 `supports_hints: bool`**。云端 provider 为 `false` 时，业务层必须**明确记录“本会话 ASR 未应用词库提示”**，不得静默丢弃 `hint_terms`（遵守“静默失败零容忍”）。DeepSeek 整理阶段的 `confirmed_terms` 完全不变。
- **超长会话与分段**：官方只“建议”手动模式单次 ≤60 秒；实验中 131.6 秒和 580 秒单会话都成功（各 1 次轮）。V2 最长 6 分钟（360 秒），策略为**服务端 provider 实时转发、不暂存，目标 30 秒、自−5 秒起遇第一个安静块 commit，+5 秒硬切**（客户端协议不变；补送限速 2×；批次 05–09 已决定，见 PRD-v2 §9），同一会话连续多次 commit，最终稿按序拼接；固定时间硬切会丢字（实验 46 字，约 1.9%），不采用。窗口内无静音的兜底（最大硬切长度/重叠）、断线后已提交段的保留、真实连续长讲话的复测，留 S2 与后续批次。超过 360 秒的会话：到点自动结束并明确提示。
- `qwen3_mlx` 保持原样，仅在 macOS Apple Silicon 主机可选；Linux 主机不展示或禁用该选项并说明原因。

### 4.2 后台 provider 配置（V2 新增功能）

- **多 provider + 单选当前**：后台维护两个独立列表——ASR provider 列表、整理 LLM provider 列表（分类 LLM 沿用现有配置，是否纳入后台列表待定）。每条记录含：名称、类型（`bailian_realtime` / `qwen3_mlx` / `openai_compatible` 等）、地址、模型名、API Key、该 provider 的超时与并发等已有参数。每个列表恰有 1 条“当前使用”；可添加、编辑、停用、删除（当前使用项不可删除）、切换。不开放会破坏协议的字段（如 `refine_protocol`、`temperature`）。
- **存储**：配置入库（新表，带版本号，沿用后台容量设置的 CAS 更新）；**API Key 加密存储**，主密钥由部署环境注入，不入库不入 Git；接口只写不读，只显示“已设置/末 4 位”。
- **校验**：保存和切换前必须通过**连通性测试**（ASR 用合成静音/短音频，LLM 用合成文本，沿用 `prepare()` 探测）；失败不生效并明确提示。
- **地址：严格白名单**：部署配置声明允许的主机**域名后缀/模式**（默认预置阿里云百炼 `*.maas.aliyuncs.com` 与 `api.deepseek.com`；百炼地址含业务空间 ID，不能写死完整主机；具体清单由 S2 列出），后台只能选择/填写白名单内的地址；校验解析结果与重定向目的地，禁止用域名伪装内网；管理员不能自行扩大白名单，新增厂商须先改部署配置并重启。`qwen3_mlx` 无地址，仅在 macOS Apple Silicon 主机可选。
- **切换语义**：新会话使用新的“当前”，在途会话用原配置完成；切换失败自动保留原配置；会话元数据记录当时使用的 provider 与模型。
- **审计**：谁、何时、改了哪条 provider 的哪些字段（不含密钥值）；不记录音频与正文。
- **兜底**：YAML 仍为启动默认；库内无配置或解密失败时回落 YAML，并在后台显示“当前来源”。
- **权限**：仅 `admin` 角色；沿用现有鉴权。

### 4.3 容量与计量

- 云端 ASR 没有 `execution_slots=1` 的本地限制，但受云端账号并发配额约束；并发上限改为 provider 配置项，且不得超过后台容量设置与部署上限。
- 用量统计新增：ASR provider 标识、音频时长（秒）、云端调用次数；用于成本核算。具体字段留 S2。

### 4.4 Linux 部署（与本稿同批评审）

- Linux 主机无 MLX：ASR 用云端 provider；如日后需要本地 GPU 识别，另立 provider（官方 `qwen-asr` + vLLM），不在本次范围。
- 远程部署前必须 HTTPS/WSS（反向代理 + 证书）；客户端服务地址只改 `desktop/src/shared/config.ts`。
- 需补充部署清单：进程管理、日志、备份、密钥注入、数据库（生产为托管/独立 PostgreSQL）、Python 与依赖版本、云端地域与出口网络。

## 7. 风险

- **隐私承诺变化**：Q1 已接受，但仍是最大风险，需 V2 PRD 与用户文案明确告知，并允许管理员不启用云端 provider。
- 云端依赖：限流、断线、账号欠费、地域不可用都会让听写失败，需要明确错误码与用户提示。
- 成本：约 0.00033–0.00066 元/秒（以官方价目页为准，本稿未读到价目原页），需用量统计与告警。
- 热词实验显示 `corpus.text` 可能让识别变差，首版不开启是合理的，但意味着云端无法保留词库对 ASR 的辅助。
- 后台可改 Key/地址扩大了攻击面：权限、审计、出口白名单与加密缺一不可。
- 样本量小，质量与延迟结论需在目标部署环境复测。
