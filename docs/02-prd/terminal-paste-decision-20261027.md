# 终端与其他应用统一粘贴决定

2026-10-27本人报告iTerm显示“当前应用不支持自动粘贴”，确认不是识别失败：已有代码终端bundle名单主动拒绝。本人明确选择“允许终端粘贴，绝不自动回车”，补充“任何地方我都可以Cmd+V粘贴过去，但是不自动回车”。据此撤销终端应用名称拒绝名单，iTerm/Terminal/Warp及其他终端与普通应用采用同一当前前台PID一次Command-V流程，不逐应用正向适配。

不合成Return/Enter、不发送/提交，不把正文末尾加换行；保留结果本身原有段落，不保证目标shell/运行中程序对多行粘贴不会自行处理。此限制在用户明确决定前已说明。当前前台生命周期/窗口仍核验，已知密码、保护、只读、禁用及非输入状态仍按通用规则处理。可读回精确匹配才inserted，否则unverified、不自动重试/学习；失败保留历史供复制。无新应用名单或模型/提示改动。

此决定取代business-rules/desktop-contract/TC-INSERT-20和目标矩阵中的“终端仅复制”旧判据。旧失败和原件保留，TC-INSERT-20重新打开按新规则复验；不是继续保留旧“拒绝终端”的pass来冒新行为通过。S1/S2/S3先同步，原生编译与类型检查后执行技术回归，再在本人自有终端新标签页实际验证一次粘贴/不自动回车。仅代码/纯策略通过不等于iTerm端到端通过。
