## 条件依据

已追踪参考产品的完整设置保存路径：renderer 校验 → 设置 hook → `store:use` → 先写本地设置 → 刷新原生快捷键集合。renderer 使用 59 条固定保留规则及自身功能重复检查；此路径没有第三方占用结果决定是否保存的通路。受控实验中，自建 Electron 进程先注册 ⌘⇧9，实际收到一次按键回调；参考产品仍接受同一组合，用户与 root 均确认新增项。用户另实按 ⌘C，报告出现系统保留提示。见静态及运行对照（内部记录，未公开）。

结论限定于该版本、该设置入口和本次共享注册；不声称穷举了所有第三方软件或所有原生路径。这已足以撤回“必须自动检出任意第三方占用”的产品要求。

## 当前有效规则

1. 保存前按平台维护的已知系统/常用操作保留表判断；至少覆盖 macOS 的 Command+C/V/X/A/S/Z/W/Q 和原有 Escape 禁用规则。命中提示“此快捷键为系统或常用操作保留，请选择其他组合”，不改变原配置。规则由本产品自行维护，不复制目标私有实现；不要求照搬 59 条数量或跨平台混用同一表。
2. 比较前归一化等价修饰符、`CommandOrControl` 的平台含义、修饰符顺序及字母大小写；同一组合的写法差异不得绕过保留规则。本产品不承诺保留表穷举全部系统/应用快捷键，也不自动感知用户后改的系统组合。
3. 不实现任意第三方软件自定义快捷键的全局枚举、占用查询或抢占检测。系统允许注册时，未报告第三方共享占用不作为失败；保存成功只表示本产品已注册并保存，不保证排他性。
4. 系统明确注册失败仍须提示“快捷键不可用，已保留原设置”；不把所有失败原因都断言为“其他应用占用”。注册新键及设置持久化成功后才移除旧键；写盘失败须释放本次新键并保留旧键/旧配置。
5. 保存成功后的界面显示与进程重启恢复仍须验收。未来配置多功能或多组时，再检查本应用内部的重复绑定；当前不扩大语音输入范围。
