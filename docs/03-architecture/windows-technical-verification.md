## 验证工具的范围

`desktop/native/windows/` 目前是独立技术探针：Win32 前台窗口与完整性检查、剪贴板单次粘贴、UI Automation 读回、光标位置、JSONL 子进程通信。探针只操作验证脚本创建的虚构文本窗口，必须显式指定目标 PID，不连接产品账号、服务端或模型。

`fixtures/electron/` 是独立 Electron 验证壳，用相同窗口参数验证不抢焦点，以及 `extraResources/voice/` 路径中的辅助程序启动。它不替代正式产品的 UI、托盘、自启、录音、取消/账号隔离、超时与安装包验收。

运行判据沿用[决策稿 §6](../02-prd/windows-version-decision-20261029.md#6-技术验证方案先于开发)。报告保留全部 15 项，阻断项为 V-01/02/03/04/07/08/09/10/14。失败、缺前置与未执行分别记录；缺项不得算通过。V-05/06/11/12/13/15 的未完成部分在正式开发及真机验收继续执行，不因技术验证排除。

## 运行与证据

先运行 Rust 编译/检查，再运行纯策略单测；macOS 的交叉类型检查不能证明 Windows 行为。Windows 运行使用固定 `windows-2025`，每次先核查交互式桌面、进程完整性、实际 Electron/Chrome/VS Code 与 Rust 版本。托管机实际权限与映像预装内容以本次预检为准，不把文档中的经验性事实当通过证据。

原始源码、编译失败、冻结清单与本地执行记录保留在已忽略的 `experiments/windows-technical-validation-20261029-01/` 和 `docs/04-test/`。远端仅在明确授权后运行；只使用虚构夹具，临时产物下载本地留证，不写入 Git 或 Release。每次远端运行使用独立输出目录和源码 SHA，不覆盖失败运行。

远端入口复用已经存在于默认分支的 **Build installers** 工作流：在 `feature/0.0.2` 上手动运行时，调用独立的 `windows-verify.yml`，不构建正式安装包；其他分支及 Release 的调用沿用原流程。这样不必为了首次注册新手动工作流而提前合并未验代码到 `main`。普通分支推送仍会触发现有 CI；技术探针只由上述手动入口启动。

触发命令为 `gh workflow run build.yml --repo uprxiao/SmartVoice --ref feature/0.0.2`。须先核对账号、远端分支 SHA 与本次本地提交，运行后独立读取 run/head SHA。**本人已于 2026-10-29 授权推送并按既定门禁继续 S0–S4；首次远端验证已执行，同范围验证修复继续沿用授权。** 运行结果、失败与证据只记本地，不据授权推定门禁通过。

报告对阶段内部分覆盖仍记 `partial`：V-04 的注入修饰键对照不能代替物理按住/释放；V-09 若本轮未观察到 Chromium 首次空读，保留实际轨迹，不把已预热的读回冒充恢复验证。V-02/03 分别安排光标插入与选区替换；V-08 安排受保护字段拒绝和不可读控件的一次真实粘贴降级。即使部分探针成功，汇总也不会据此宣布 9 项阻断验证通过。阻断项的未完成参数不能移到 S4 后补。

实现核查依据：[Microsoft OpenClipboard 文档](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-openclipboard)说明 NULL 所属窗口与后续写入的限制；[GitHub 手动运行工作流文档](https://docs.github.com/en/actions/how-tos/manage-workflow-runs/manually-run-a-workflow)说明默认分支注册及选择分支运行的要求。现有决策稿的自动复制表述已按同稿 Q7 统一为用户手动“复制结果”，不新增产品决策。

## 继续工作的门禁

1. 完成独立探针与验证脚本，编译检查和必要单测通过，本地提交。
2. 核对远端同步授权后推送 `feature/0.0.2`，执行 Windows 技术验证，下载完整证据并逐项判定。
3. 任一阻断项未通过，继续修订探针/验证方案并保留失败；不能据构建成功进入 S4。
4. 阻断项通过后，依次完成 Windows S0、S1、S2、S3 的产物与评审，并在 `docs/README.md` 登记阶段依据。
5. S4 按已评审用例开发。本版主要改 desktop；server/admin 核对契约影响和回归范围，有依据地记录是否需要修改。
6. S5 由本人在 Windows x64 真机执行安装、中文输入法、麦克风、剪贴板历史、多屏、终端等验收；Win10/11 按 Q6 记录实际覆盖，未验版本不记通过。
