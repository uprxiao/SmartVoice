# 实例锁恢复专项用例

2026-11-11，在需求确认及 [S2](../03-architecture/instance-lock-recovery.md) 后生成；不替代既有 ASR、音频、跨平台验收。夹具只使用虚构数据、独占测试数据库与自有子进程。执行结果另存本地忽略目录。

| 编号 | 场景 | 判定标准 |
| --- | --- | --- |
| LOCK-01 | 健康连接及真实持锁 | 探测 true；原连接提交不会释放会话级锁；无误保护 |
| LOCK-02 | 连接缺失/关闭/失效，后端变化，锁不存在 | 原因分类准确，探测 false；无重新获取锁；不记录正文、DSN、异常消息 |
| LOCK-03 | mutex/SQL/commit 超时或异常 | 原 2 秒预算不变；阶段、耗时、异常类别可追溯；异常文本中的敏感 canary 不出现在日志 |
| LOCK-04 | 实际服务原持锁连接被终止/释放锁 | 独占库精确匹配 PID 与锁；实际 TCP 服务停止接单、清理并以 75 退出；旧连接无锁，继任实例 ready |
| LOCK-05 | 生产监听入口观测 fenced | 无手工设置 should_exit；真实入口触发既有关闭链路，清理完成前不报告正常退出；非 systemd 也不留活着的故障服务 |
| LOCK-06 | 原有取消及普通 SIGTERM | 原事务回滚、旧任务隔离、停止顺序通过；正常停止不误记实例锁错误或失败码 |
| LOCK-07 | systemd 通知 | 真 UNIX socket 收到 READY/周期 WATCHDOG；错误 WATCHDOG_PID 不发送；抽象 socket 与无 systemd 环境行为正确 |
| LOCK-08 | 实例保护后清理卡住/事件循环卡住 | 独立 Linux unit 超过 watchdog 后主/子进程均终止，新实例才运行；清理完成前不重新放行业务 |
| LOCK-09 | 连续启动失败 | 独立 unit 中重启受 StartLimit 限制；保留失败状态与日志 |
| LOCK-10 | 既有部署更新 | 更新文件摘要匹配，unit 校验通过，进程代际改变，watchdog 持续更新；外部 HTTPS 数据库/ASR/LLM ready，鉴权接口仍拒绝匿名请求 |

LOCK-08/09 只在独立临时 unit 注入故障，不在正式服务注入；LOCK-10 不宣称已重新完成人声、模型质量或客户端插入验收。
